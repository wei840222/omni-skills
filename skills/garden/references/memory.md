# Memory Template — Garden

## Initial Setup

After `SKILL.md` resolves `<state_root>`, obtain the named creation consent described there before creating `<state_root>/memory.md`. Use the memory template in `assets/garden-data-templates.md` as the sole template authority.

Create `<state_root>/plants/`, `<state_root>/zones/`, `<state_root>/log/`, `<state_root>/climate.md`, and `<state_root>/harvests.md` after the user enables the corresponding detailed tracking.

## Update Procedure

1. Confirm the record type and the resolved `<state_root>` with the user when tracking has not already been enabled.
2. Write only user-provided facts or user-approved summaries.
3. Report the created or updated path after a successful write.
4. Keep the other candidate state directories unchanged.

## Record Scope

- Start with `<state_root>/memory.md` for approved garden context.
- Add detailed files only for records the user chooses to track.
- Keep garden state under `<state_root>`; an optional host-provided `MEMORY.md` entry requires its own explicit approval.
