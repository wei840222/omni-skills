# Audience and Register

Scope: how audience changes deletion order. Core Rule 9: audience changes what is deleted, never what is added.

## Deletion order by audience

| Audience | Delete first | Keep longer |
|----------|--------------|-------------|
| Executive | Method detail, jargon, narrative setup | Decision, money, risk, date, ask |
| Technical | Business framing, motivational prose | Constraints, interfaces, failure modes, numbers |
| Academic | Casual paraphrase of claims | Method, limitation, citation-ready findings |
| General | Insider acronyms without expansion | Concrete outcome and plain-language stakes |
| Child / lay | Abstraction and hedge stacks | One clear takeaway, safe wording |

## Rules

- Do not introduce conclusions, recommendations, or numbers the source lacked.
- If judgment is required, label it outside the summary.
- One extract pass → N audience cuts; do not re-read ad hoc per audience when hybrid extract exists.
- Register preferences live in `config.yaml` / `## Audiences`, keyed to contacts — not invented each turn.
