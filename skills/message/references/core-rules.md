# Core Rules

Apply these before every outbound draft. Prefer the positive action in each rule; the failure mode is the reason, not the script.

## 1. Require explicit commitment approval

Draft timelines, pricing, legal terms, availability, and money moves for human review, then wait for per-transaction approval before send.

- An AI saying "we can deliver by Friday" can become career damage.
- When commitment level is unclear, ask one clarifying question first.

## 2. Escalate high-stakes threads

Draft for human review and require approval before send when any of these apply:

- Investors, board, press, lawyers
- Client complaints or wording such as urgent / legal / disappointed
- Condolences, relationship conflict, or first contact with an important person

Full matrix and keyword list: `references/escalation.md`.

## 3. Match the human's style

Read the user's last ~5 messages on that channel before drafting.

- Mirror their typical length, emoji pattern, greeting/closing, and reply speed.
- Keep filler they never use out of the draft ("Hope you're doing well!" only if they write that way).
- Prefer their brevity: many humans send "ok"; padded paragraphs read as automation.

## 4. Choose channel by urgency

| Urgency | Channel |
|---------|---------|
| Production down | Call, then Slack/Teams |
| Same-day needed | Slack/Teams DM |
| This week | Email |
| FYI only | Email with no action needed |

- Use call/Slack-class channels for true urgency; email is a poor incident path.
- Use email (or another formal record) for external client commitments.
- Keep formal client work off casual group Slack unless the user already does that.

## 5. Treat timing as a social signal

- Instant replies can reveal automation; add natural delay when the user's pattern is slower.
- Recipient-local 03:00 → schedule for their morning unless they asked for night delivery.
- Email can wait hours. Slack/Teams DMs often expect a reply within about an hour during working time.

## 6. Confirm context before send

- Verify the active chat, thread, and recipients.
- Skip re-introductions after a long history with the same person.
- In groups, reply when you add value; constant replies read as bot-like.
- When the target group is uncertain, ask once instead of guessing.
