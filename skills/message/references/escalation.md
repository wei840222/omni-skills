# Escalation Rules

## Require review before sending

### Financial

- Payment confirmations
- Pricing discussions
- Invoice disputes
- Refund requests
- Budget approvals

### Legal

- Mentions of lawsuit, legal, terminate, contract, NDA
- Partnership agreements
- Terms and conditions
- Compliance matters

### High-stakes relationships

- Investors and board members
- Enterprise clients
- Press and media
- Lawyers
- C-level executives

### Emotional / personal

- Condolences
- Relationship issues
- Conflict resolution
- Apologies for serious matters
- Bad-news delivery

### First contact

- First message to an important new contact
- Introductions to senior people
- Cold outreach on behalf of the user

## Always draft for review

### Investor communications

- Updates, reports, asks
- Bad news especially

### Client escalations

- Complaints
- Churn signals
- Scope changes
- Timeline discussions

### Team-sensitive

- Performance feedback
- Organizational changes
- Anything that could become an HR issue

## Keyword triggers

Auto-escalate drafts that contain (case-insensitive) signals such as:

- urgent, ASAP, emergency
- legal, lawsuit, lawyer
- frustrated, disappointed, angry, concerned
- cancel, terminate, refund
- board, investor, press
- deadline, contract, pricing

Treat near-synonyms the same way when intent is clear (for example furious → angry/concerned class).

## Safe to handle with standing authorization

Only when the user has already authorized this class of send in the current task or a durable policy skill such as `escalate`:

### Routine operations

- Meeting scheduling with factual times
- Status updates using pre-approved content
- Factual information answers
- Short acknowledgments ("got it", "thanks")

### Pre-approved templates

- Standard replies the user already approved
- FAQ answers
- Scheduling confirmations

### Low-stakes social

- Group-chat reactions
- "Running late" notes the user asked to send
- Birthday wishes after the draft was approved

## Golden rule

When uncertain: **ask and wait for approval.**

A missed message can be sent later. A bad message cannot be unsent.
