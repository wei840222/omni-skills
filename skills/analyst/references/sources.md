# Official Sources Map — Analyst

Use these primary sources when citing SQL style, visualization practice, causal caution, or statistical communication. Prefer full URLs in PR notes and user-facing citations. This skill stays warehouse- and vendor-neutral.

## SQL style and readability

- **GoogleSQL / BigQuery best practices** — query structure and performance-oriented patterns via https://cloud.google.com/bigquery/docs/best-practices-performance-overview
- **dbt Labs — How we structure our dbt projects** — model layering and readable analytics SQL culture via https://docs.getdbt.com/best-practices/how-we-structure/1-guide-overview
- **SQL Style Guide (GitLab)** — consistent formatting defaults for collaborative queries via https://about.gitlab.com/handbook/business-technology/data-team/platform/sql-style-guide/

## Visualization and chart choice

- **Data Visualization Society / community practice** — chart intent over decoration (orient from established chart-selection guidance; pair with org standards) via https://www.datavisualizationsociety.org/
- **NIST Engineering Statistics Handbook — Exploratory Data Analysis** — distribution-first exploration habits via https://www.itl.nist.gov/div898/handbook/eda/eda.htm
- **UW Interactive Data Lab — Visualization literature overview** — research-backed encoding principles via https://idl.cs.washington.edu/papers/

## Causation, experiments, and caution

- **UK MRC / NIH experimental design orientation** — pre-specify outcomes; avoid post-hoc story shopping (use live org experiment guides when available) via https://www.nihr.ac.uk/researchers/
- **Open Science Framework — Preregistration** — why analysis plans reduce cherry-picking via https://help.osf.io/article/158-create-a-preregistration
- **American Statistical Association — Statement on Statistical Significance and P-Values** — communicate uncertainty without overselling via https://www.amstat.org/asa/files/pdfs/P-ValueStatement.pdf

## Metric definitions and data quality

- **Data Management Body of Knowledge (DAMA) orientation** — definitions, lineage, and quality dimensions via https://dama.org/
- **ISO 8000 overview (data quality)** — quality characteristics vocabulary via https://www.iso.org/standard/81745.html

## How to use these sources in-session

- Cite the matching group when claiming SQL readability, chart choice, causal caution, or metric quality.
- Prefer the user's warehouse docs and certified metric catalog over generic guides when they conflict.
- Do not invent vendor-specific function behavior from memory; open the live dialect reference first.
- Treat benchmarks and p-value rhetoric as communication aids, not automatic decision rules for the user's domain.
