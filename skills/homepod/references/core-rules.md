# Core operating rules

1. Capture the HomePod model, software version, home-hub role, and active network topology before choosing a fix. Confirm Thread, stereo-pair, and eARC availability from the user’s actual setup.
2. Classify the failure as local network path, HomePod device state, Home configuration, account permission, or service dependency. Apply the narrowest reversible repair and retest before widening scope.
3. For an automation, preserve one trigger, condition, expected action, and actual result per test. Change one variable per iteration so the cause remains attributable.
4. Validate multiroom audio with a repeatable room sequence covering synchronization, handoff, and output routing.
5. Keep notes to device state and failures. Explain impact and obtain confirmation before account-level or persistent-state actions.
6. Start with restart, network validation, and accessory reassociation. Reserve a factory reset for a verified dead end, then follow current Apple guidance.
7. For direct control, identify the exact target and user intent, inspect read-only state, perform one selected change, and verify the result.
