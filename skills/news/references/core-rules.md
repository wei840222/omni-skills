# Core Rules

## 1. Build profile before bulk delivery

On first interaction (no usable `<state_root>/memory.md`), ask for:

- **Specific interests** — not generic buckets (“AI chip supply”, not just “tech”)
- **Mix** when several interests exist (e.g. “70% AI, 30% markets”)
- **Format** — bullets, short narrative, or headlines-only
- **Timing** — morning, evening, weekly, or on-demand

Write the answers to `<state_root>/memory.md` only after brief consent on first durable write. Seed the tree from `assets/memory-template.md` when creating state.

## 2. Check memory first

Before every briefing, read `<state_root>/memory.md` when it exists. Tailor topics, depth, and format to that profile. If the file is empty or stale relative to the user’s last explicit correction, reconfirm the changed fields only.

## 3. Facts first, analysis second

For each item:

1. What happened (concrete event)
2. When it broke / last confirmed
3. Named source(s)
4. Optional analysis or “why it matters” after the facts

Do not open with opinion, speculation, or unverified social posts presented as fact.

## 4. Multi-source on contested topics

When the topic is disputed, high-stakes, or polarized:

- Present **at least two** independent sources
- Note where they agree and disagree
- State known editorial leanings when relevant and evidenced
- Prefer primary documents (filings, official releases) over secondary commentary when available

If only one source is available, say so explicitly and mark confidence as limited.

## 5. Stick to verified facts

- If uncertain whether something happened, say so
- Never invent headlines, quotes, numbers, or timelines
- Separate “reported by X” from “confirmed”
- Time-stamp items; do not present stale stories as breaking without labeling them

## 6. Update memory from engagement

After the briefing:

- Notice which items the user expands, skips, or corrects
- Periodically propose a small profile adjustment (interest mix, format, blocked topics)
- Append light signals to `<state_root>/history.md` when the user accepts durable learning
- Never silently rewrite core interests without a clear user cue

## 7. Briefing size and pacing

- Default morning briefing: **5–7** items unless the user asks for more
- Group by interest when the mix is multi-topic
- Offer one optional “deeper dive” slot rather than dumping every related link
