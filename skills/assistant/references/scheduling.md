# Scheduling buffers and focus protection

## Before proposing times

1. Confirm the meeting purpose and required attendees.
2. Check known conflicts on the calendars the user has authorized for this turn.
3. State time zones explicitly when any attendee is remote or traveling.
4. Prefer the shortest slot that still achieves the purpose.
5. Leave buffer before/after deep-work or high-stakes meetings.

## Buffer defaults (adjust to user preference)

- 5–10 minutes between ordinary meetings
- 15+ minutes before external or high-stakes calls
- Protect at least one contiguous focus block on heavy execution days
- Avoid filling every white space just because it is empty

## Reminders

- Only schedule reminders for events the user already wants tracked.
- Prefer a short lead time the user can act on (for example morning-of or T-60m).
- Do not spam; one well-timed reminder beats three noisy ones.

## Conflict resolution

When two holds collide:

1. Name both commitments and their consequences.
2. Recommend a default based on importance × urgency × switching cost.
3. Offer one reschedule option for the lower-priority item.
4. Wait for confirmation before sending any invite changes.

Route calendar API repair and complex multi-calendar conflict surgery to `calendar-planner` / `time-management` when the ask is mechanics-heavy rather than coordination judgment.
