# Communications and inbox handling

## Thread summary template

When summarizing a long thread, return:

1. **Decision needed** (one line)
2. **Key points** (3–5 bullets max)
3. **Open actions** with owner + deadline when known
4. **Risks / unknowns**
5. **Suggested next reply** (draft only, pending approval)

Never paste entire message bodies into durable state unless the user explicitly asks to keep them.

## 4Ds inbox pass

Process items in short batches:

| D | Meaning | When |
|---|---|---|
| Delete | No value, no obligation | Noise, expired FYI |
| Delegate | Someone else owns it | Include context + deadline when handing off |
| Defer | Needs time later | Park with a date or waiting-for |
| Do | ≤2 minutes or already in hands | Finish immediately |

Do not present a raw unread count as the primary UI. Present actionable batches (“3 items need a decision”).

## Drafting rules

- Match the user’s stated voice when known; otherwise stay plain and direct.
- Put the ask and deadline in the first screen of text.
- Offer one recommended option plus one alternative when choices exist.
- Stop before send: external messages require explicit approval.

## Batching

Group by channel, project, or sender. One batch of seven intro requests beats seven separate interruptions. Protect focus blocks from reactive drip.
