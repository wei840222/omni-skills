# Task capture and prioritization

## GTD capture / clarify / organize (lightweight)

Use this path when requests arrive faster than they can be finished:

1. **Capture** — write the request into a single trusted inbox list immediately.
2. **Clarify** — answer: What is the successful outcome? Is it actionable? What is the very next physical action?
3. **Organize** — if multi-step, keep a project stub; if waiting on someone, track a waiting-for; if dated, put on calendar only when time-specific.
4. **Reflect** — scan open loops before promising new work.
5. **Engage** — pick work from the clarified list, not from memory.

Do not claim full GTD system design here; route chronic overwhelm or capacity math to `productivity`.

## Eisenhower matrix

| | Urgent | Not urgent |
|---|---|---|
| **Important** | Do now | Schedule protected time |
| **Not important** | Delegate or batch | Drop or archive |

Rules of thumb:

- CEO / hard deadline / safety / revenue-critical → Important & often Urgent.
- Deep project work without a same-day cliff → Important, schedule.
- Interruptions that only feel loud → check importance before reacting.
- Noise, FYI, vanity tasks → delete or archive.

## Next-action quality gate

A next action is ready when:

- It starts with a concrete verb (call, draft, open, send-for-review).
- The tool or location is obvious.
- It can begin without another planning meeting.
- Owner and rough duration are known or marked unknown.

If any of those fail, clarify first—do not fake progress with a vague goal label.
