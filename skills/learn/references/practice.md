# Practice — Difficulty and Feedback

Load for deliberate practice design, success-rate tuning, and feedback latency.

## ~85% success target

Wilson-style guidance: train near ~85% correct. Above ~90% the material teaches little; below ~75% the learner guesses and encodes errors. Count hits over the last 20 attempts.

- Too easy → speed pressure, remove scaffolding, widen scope
- Too hard → shrink the unit, keep the ambition

## Desirable difficulties

Block until roughly ~80% within-session success, then interleave with neighbours. Massed practice feels better and retains worse on delayed tests (Bjork desirable difficulties; see `research-sources.md`).

## Feedback latency budget

| Kind | Max latency |
|------|-------------|
| Drill | Same minute (self-correct) |
| Exercise | Same session |
| Project | ≤48 hours to review / test / working signal |

If latency will exceed the budget, choose a proxy **before** practice starts: automated tests, rubric, recording, diff against a reference.

## No mentor

Rank substitutes by latency: automated checks → recorded self-review against a rubric → peer swap → paid review. Build the rubric from the exit test, not from vibes.
