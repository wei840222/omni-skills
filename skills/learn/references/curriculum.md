# Curriculum — Exit Tests and Sequencing

Load when planning a path, sizing time, or cutting scope.

## Exit test first

Write an observable performance with conditions before picking a resource:

- Action the learner can demonstrate (ship, perform, solve, teach)
- Constraints (time box, unaided, from a blank repo / cold start)
- Pass bar a third party could grade

Bad: "understand Rust", "get good at chess".
Good: "ship a REST API with auth and tests from a blank repo in a weekend without copying a tutorial".

Work backwards from the exit test into a short sequence of milestones. Each milestone has its own smaller exit check. Cut anything that does not move the next check; write the cut list so scope creep is visible.

## Time as a range

`weeks = total_hours ÷ weekly_hours`, then quote `weeks` to `2 × weeks`. State what the upper bound assumes (illness, travel, harder-than-expected units). Never pin a single calendar date as the success criterion.

## Plan review

Put `plan_review_weeks` (default 4) into `## Due`. At review, compare planned vs actual hours and milestone evidence; revise the sequence, do not guilt the learner into the old fiction.

## One primary resource

Pick one spine resource that covers the exit test path. Everything else becomes lookup. Parallel "I'll do three courses" usually finishes zero.
