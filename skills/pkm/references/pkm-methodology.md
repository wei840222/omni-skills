# PKM methodology

## Purpose

A Zettelkasten-style personal knowledge base is a web of connected thoughts, not merely a collection of files. Its useful building blocks are an inbox, a note archive, and a way to retain sources and entry points. Use this reference when setting up or evolving the user's workflow.

## Capture and processing

1. Capture unprocessed material quickly in `inbox.md` so a useful idea is not lost while its destination is uncertain.
2. In a later processing pass, extract one durable idea per note. Write it so the user can understand it without reopening the original source.
3. Preserve source URLs, attribution, and capture dates when the origin matters.
4. Connect the new note to existing ideas when the relationship aids later navigation; links should express a real association rather than an arbitrary filing rule.
5. Remove an inbox entry only after its information was retained in a durable note, task system, or explicit discard decision.

## Atomicity, linking, and structure

- **Atomicity:** Keep each note focused on one main concept so it can be reused in more than one context.
- **Autonomy:** Include enough explanation for a note to remain meaningful on its own.
- **Connectivity:** Use links to build paths through related ideas; search alone does not reveal all useful context.
- **Entry points:** Create indexes, MOCs, or curated tags when recurring clusters need a navigable starting point.
- **Organic growth:** Begin with a flat archive and add structure in response to actual retrieval friction, not anticipated complexity.

## Practical checks

Before adding a note, check whether the archive already contains the concept. Before adding folders or a complex taxonomy, verify that the current archive is hard to navigate. Before syncing or sharing, confirm the user wants the selected notes to leave their local workspace.
