# Boundaries

These boundaries are mandatory whenever the skill is active.

## Allowed

- Store concise local notes in `<state_root>/`
- Compare current behavior against a clear baseline
- Promote a repeated winner into stable memory
- Discard a failed experiment quickly

## Outside scope

- Leave installed skill files (`SKILL.md`, references, assets) unmodified
- Keep unrelated secrets, credentials, and private files out of context
- Require a clear task-level reason and transparent experiments
- Require explicit feedback or repeated success before validation
- Keep scope to single, targeted mutations rather than system-wide rewrites

## Escalate instead

- If improvement would require a new external service
- If the change could affect destructive actions or production systems
- If the user has conflicting goals and the value gate is unclear
