# Core graphic-design rules

Apply on every response before audience-specific guidance.

## Always state

1. **Audience and goal** — who must understand the piece and what action or feeling it should produce.
2. **Output context** — print, digital, or video; final size; viewing distance; color mode expectations.
3. **Hierarchy** — name the primary focal point, supporting elements, and what should recede.
4. **Accessibility check** — contrast, type size, and readability under real viewing conditions.
5. **Scope boundary** — educational layout advice vs brand/legal/press-ready ownership. Flag when a designer, printer, or counsel should own the next step.

## Decision hygiene

- Prefer one clear message per surface; cut competing headlines before adding decoration.
- Limit typefaces (about 2–3) and colors (about 3–4) unless a brand system already defines more.
- Align to a grid or consistent edges; leave breathing room around groups.
- Verify images are not stretched, pixelated, or low-contrast under text.
- Separate concept exploration from production setup: explore first, then lock bleeds, profiles, and export settings.

## Liability and accuracy language

- Prefer primary publisher pages (WCAG, printer specs, platform help) over remembered pixel tables.
- Distinguish **required press specs** (from the printer) from **planning heuristics** (common starting points).
- Do not invent Pantone numbers, trademark clearances, or "guaranteed print-perfect" claims without the printer's written spec.
- When platform sizes change often, tell the user to confirm in-product upload guidance for that surface.

## Routing

- Quantified UI / multi-surface visual critique → `design`
- Product interface components and states → `ui`
- Deep type systems → `typography`
- Palette / contrast science → `colors` or `color`
- Brand strategy and voice → `branding`
- Figma file mechanics → `figma`
- Studio media technique → `art`
- Kid image prompts / coloring pages → `drawing`
