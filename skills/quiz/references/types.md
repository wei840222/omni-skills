# Quiz types

Choose one primary type before drafting items. Mixed goals (e.g. learn + capture email) need an explicit primary outcome.

## Knowledge

**Purpose:** assess learning, certify competency, reinforce material.

**Practices:**

- Align every item to a stated learning objective
- Mix difficulty (easy → medium → hard) to build confidence
- Prefer immediate feedback + explanation for learning; delay feedback when assessment purity matters
- Allow review of incorrect items after completion when the goal is mastery
- Shuffle items/options on retakes when security matters

**Formats:** multiple choice (4–5 options), true/false (sparingly), fill-in, matching, ordering.

**Scoring:** percentage or points; optional partial credit on multi-part items.

## Personality

**Purpose:** engagement, self-discovery, shareability.

**Practices:**

- Keep length short (about 5–12 questions)
- Every answer maps to one or more outcome traits
- Results feel personalized and constructive (not insulting)
- Offer a shareable summary line or image concept

**Formats:** forced-choice scenarios, image pick, sliding scales, ranking.

**Scoring:** trait tallies; highest score (or dominant pattern) selects the outcome.

**Outcomes:** usually 4–8 types, each with name, description, implication, and one next action.

## Assessment / diagnostic

**Purpose:** diagnose level, gaps, or fit; recommend next steps.

**Practices:**

- Cover multiple competency dimensions explicitly
- Prefer scenario / application items over pure trivia
- Report strengths and growth areas, not a single vanity score
- End with concrete recommendations tied to weak dimensions

**Scoring:** multi-dimensional rubric; separate scores per competency.

**Results:** dimension breakdown (table or radar concept) + narrative + recommended actions.

## Lead generation

**Purpose:** capture contact info by gating valuable results.

**Practices:**

- Result value must exceed email/contact friction
- Keep the quiz short (about 5–8 questions)
- Show progress; avoid surprise gates mid-flow when possible
- Be explicit about what the user receives after submit
- Do not over-collect PII; store contacts outside the skill package

**Scoring:** often personality- or recommendation-style outcomes rather than hard right/wrong.

## Trivia / entertainment

**Purpose:** fun, social play, light competition.

**Practices:**

- Fast items; optional timers only when they add fun without cruelty
- Leaderboard or shareable score when the context is social
- Avoid punitive failure copy

**Scoring:** simple points; optional streaks.

## Type selection checklist

- [ ] Primary goal written in one sentence
- [ ] Length budget matches attention (learning can be longer; marketing shorter)
- [ ] Scoring model matches goal (accuracy vs traits vs dimensions)
- [ ] Results include a next action
- [ ] Accessibility and mobile constraints acknowledged for the delivery surface
