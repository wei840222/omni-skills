# Privacy, consent, and suppression

Most rows are about people who never agreed to be filed. Minimize.

## Suppression (`do-not-surface.md`)

Before birthday sweeps, briefs, intro suggestions, or reconnect lists:

1. Read `do-not-surface.md`.
2. Skip matches, including names just typed in chat if listed.
3. Keep reason codes distinct: `deceased`, `estranged`, `breakup`, `user-request`.

Death vs fallout need opposite handling if the user raises the person first.

## Consent ceiling

- Default `sensitive_details: minimal` — store topic markers, not diagnoses, affairs, salaries.
- Never record credentials, codes, or passwords (pointers only).
- Nothing is written about a person the user has not raised in context, except maintenance the user requested (import/merge).

## Deletion request

1. Suppress first (keep opt-out/suppression proof).
2. Delete person file, contacts row, and skill-controlled exports.
3. Log copies touched.
4. Do not resurrect from candidate imports without explicit user action.

For general third-party data rights framing see `sources.md` (GDPR erasure overview). This skill stays local-first and does not implement a legal compliance engine.
