# Optimization — readability, layout, SEO packaging, voice

Load this file when calibrating audience difficulty, digital scan layout, or web metadata.

## Readability bands

Calibrate sentence length and jargon to the named audience. Use Flesch–Kincaid **as a planning band**, not a fake precision score, unless the user runs a real calculator.

| Audience | Planning grade band | Avg sentence length | Jargon |
|---|---|---|---|
| General public | ~6–8 | ~15–20 words | <5% unexplained terms; define the rest |
| Professional | ~9–12 | ~18–25 words | <15% field terms; define first use when mixed audience |
| Technical | ~13–16 | ~20–30 words | Field terms OK; still define rare acronyms once |

Plain-language anchors (Digital.gov / plain language principles): write for the audience; prefer short sections; prefer active voice and present tense; avoid unnecessary jargon.

Active-voice floor: aim for ≥70% active sentences unless passive is required for unknown actor or emphasis.

## Engagement / scan structure (digital)

NN/g web-reading research: most users scan; scannable text outperforms walls of prose.

| Element | Digital default | Print-leaning default |
|---|---|---|
| Subheadings | About every 150–200 words; meaningful, not clever-only | About every 300–400 words |
| Paragraphs | 2–3 sentences typical; hard cap ~5 | Slightly longer OK if still one idea |
| Quotes | Every 3–4 paragraphs when sources exist; length ~5–25 words | Same, less frequent OK |
| Lists | When enumerating 3+ parallel items; roughly every 500–700 words if the piece is instructional | Use sparingly in pure narrative features |
| Transitions | Prefer concrete logical links ("However", "As a result", "Meanwhile") over empty filler | Same |

One idea per paragraph. Lead with the paragraph's point in the first sentence so scanners catch it.

## People-first SEO packaging

Google Search Central: create helpful, reliable, people-first content; titles should be descriptive and non-shocking; snippets/meta descriptions summarize the page honestly.

| Element | Practice |
|---|---|
| Article substance | Original value; do not spin other coverage without added reporting or analysis the user owns |
| Title / `<title>` | Descriptive and concise; useful summary of the piece; avoid bait exaggeration |
| Meta description | One or two natural sentences that describe the page; Google may rewrite from on-page text |
| Header hierarchy | One H1-equivalent title; H2 about every 300–500 words for long digital pieces; H3 for true subsections |
| Keyword use | Primary phrase appears naturally in title, lead, and one subhead when relevant — no density theater |
| External links | When citing, prefer 2–3 authoritative references per ~1000 words of reported web content |

**Content-first rule:** finish the article for readers, then tune metadata. Never reverse the order in a way that warps claims.

Title length and meta length are **display-sensitive**. Prefer concise titles that survive truncation on mobile; treat legacy "50–60 / 150–160 character" tips as soft heuristics only, not hard Google limits (Search Central documents truncation behavior rather than a fixed public character quota).

## Publication voice checklist

Before delivery:

- [ ] Form voice matches brief (news / opinion / feature)
- [ ] Readability band matches audience
- [ ] Active-voice floor met or passive uses are intentional
- [ ] Subheads are informative
- [ ] SEO title + description (if requested) do not overclaim
- [ ] No invented sources or statistics
