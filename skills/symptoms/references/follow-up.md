# Later check-ins

Use these only when the user returns, asks for a reminder, or asks what changed. Do not invent a schedule the user did not accept.

| Moment | Ask | Write |
|---|---|---|
| A few hours later, if they asked to be checked | Any change in severity, location, or associated symptoms? | A follow-up line on the same entry in `<state_root>/log/YYYY/MM/DD.md` |
| After they say it eased | What coincided with the change? | Their words under `Change`, not a cause |
| Next day | Did it return, and at what severity? | A new entry only if they describe a new start |
| Repeated episodes | How many times in the window, and which context repeated? | `<state_root>/patterns.md` only if they want the pattern kept |

A pattern line states the count and the shared context. Example: `3 headache entries in 10 days; each note mentioned short sleep.` It does not say the short sleep caused the headache.

If a check-in reveals a red-flag feature, switch to `references/red-flags.md` before adding commentary.
