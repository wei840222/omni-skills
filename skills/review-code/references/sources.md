# Review-Code Research Sources

Gate 6 notes for review defaults used in this skill. Prefer primary guidance over anecdotal checklists.

## Secure code review practice

- OWASP Code Review Guide (v2) — structured manual review focus areas, threat-informed inspection, and common vulnerability classes via https://owasp.org/www-project-code-review-guide/
- OWASP Application Security Verification Standard (ASVS) — verification requirements that map review findings to security controls via https://owasp.org/www-project-application-security-verification-standard/
- NIST SP 800-218 Secure Software Development Framework (SSDF) — secure review and verification practices inside the development lifecycle via https://csrc.nist.gov/pubs/sp/800/218/final

## Pull request and change hygiene

- Google Engineering Practices — What to look for in a code review — correctness, complexity, tests, naming, style, and documentation expectations via https://google.github.io/eng-practices/review/reviewer/looking-for.html
- Google Engineering Practices — The Standard of Code Review — speed vs thoroughness trade-offs and how reviewers prioritize issues via https://google.github.io/eng-practices/review/reviewer/standard.html
- Conventional Comments — consistent label prefixes for blocking vs non-blocking review feedback via https://conventionalcomments.org/

## Testing and risk evidence

- OWASP Testing Guide — test ideas that complement static review when runtime proof is required via https://owasp.org/www-project-web-security-testing-guide/
- NIST SSDF PW.7 / PW.8 family (within SP 800-218) — review and test evidence expectations before release via https://csrc.nist.gov/pubs/sp/800/218/final
