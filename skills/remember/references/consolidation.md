# Memory consolidation

## During a session

Record an explicit correction in `corrections.md`, a preference in `preferences.md`, a decision and rationale in `decisions.md`, and a commitment with a deadline in `commitments.md` when the user asks for durable retention.

## Review

For a requested end-of-session or periodic review:

1. Check promises, confirmed preferences, durable decisions, and changed facts.
2. Mark entries that need verification instead of presenting them as current.
3. Preserve history for a change: record an update such as `[Updated 2026-02-11] Was: Friday, Now: Monday` and make the newer confirmed value active.
4. Ask the user to clarify when dates and sources do not establish a reliable winner.

## Maintenance

Archive completed commitments older than 30 days and contexts inactive for 60 days when the user requests maintenance. Delete only information that is incorrect, useless, privacy-sensitive, or explicitly requested for removal; archive when later context could still help.

Use the staleness test for each entry: "If I retrieve this in six months, will it help or mislead?"

| Usually helps | Usually misleads |
| --- | --- |
| Preferences and principles | Current weekly project status |
| Hard-learned corrections | Temporary blockers |
| Relationship roles | Unverified assumptions |
| Decision rationale | Superseded active details |
