# Dimensions to detect

Consult this reference only when classifying an explicit communication preference.

## Response structure

- Length preference (concise vs detailed)
- Format (bullets vs prose vs mixed)
- Headers or sections vs flat text
- Code blocks: fenced vs inline

## Tone and formality

- Casual vs professional
- Emoji tolerance (none / minimal / frequent)
- Specific emojis the user prefers
- Humor level
- Directness (blunt vs softened)

## Technical level

- Jargon tolerance
- Explanation depth needed
- Assumed prior knowledge vs needed context

## Interaction patterns

- Proactive suggestions
- Confirmations before acting
- Progress-update frequency
- Preferred autonomy level

## Communication openers

- Phrases the user wants omitted
- Preference for jumping directly to an answer
- Preference for a brief acknowledgment first

## Content preferences

- Examples: wanted or not
- Analogies: helpful or distracting
- Links: inline or collected at the end
- Warnings and caveats: upfront or footnotes

## Context-specific preferences

- Different style for different topics
- Time-sensitive requests that need more concise responses
- Creative tasks that need more exploratory responses

## Rejected patterns

Record explicitly rejected patterns in `<state_root>/rejected.md` and use the user’s stated alternative in later responses.
