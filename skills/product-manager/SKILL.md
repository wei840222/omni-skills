# Product Management Rules

This skill is stateless and does not store local configuration or persistent user state.

Load the specific reference file into your context based on the current product management phase or task:

| Reference File | When to load |
|---|---|
| `references/domain-knowledge.md` | When verifying PM frameworks, discovery habits, roadmap/PRD practice, or North Star metrics against current sources. |
| `references/discovery.md` | When trying to understand user problems, validate ideas, or analyze competitors. |
| `references/prioritization.md` | When deciding what to work on next, evaluating impact vs effort, or handling stakeholder requests. |
| `references/roadmapping.md` | When planning future work, communicating timelines, or aligning on outcomes. |
| `references/requirements.md` | When defining user stories, acceptance criteria, or managing scope. |
| `references/working-with-engineering.md` | When collaborating with developers on technical implementation and trade-offs. |
| `references/working-with-design.md` | When collaborating with designers on user experience and edge cases. |
| `references/stakeholder-management.md` | When keeping the wider team informed and handling feedback or disputes. |
| `references/metrics.md` | When defining success, analyzing data, or planning experiments. |
| `references/launch.md` | When preparing to release a product or feature, including checklists and post-launch reviews. |
| `references/common-mistakes.md` | When reviewing strategies to avoid anti-patterns like being a feature factory or overspeccing. |
